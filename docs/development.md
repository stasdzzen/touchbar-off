# Разработка и технические ограничения

## Сборка

Следующая локальная версия: **1.3.1 (build 6)**.

Нужны macOS и Apple Command Line Tools (`xcode-select --install`) либо Xcode. Homebrew и сторонние зависимости не нужны.

```sh
git clone https://github.com/stasdzzen/touchbar-off.git
cd touchbar-off
./build-app.sh
```

Сборка появится в `build/Touch Bar.app`. Скрипт использует архитектуру текущего Mac, минимальная версия macOS — 13.0. Это нижняя граница сборки, а не доказанная совместимость со всеми версиями системы. Иконки генерируются локально через AppKit и `iconutil`. Bundle получает ad-hoc подпись; Developer ID и нотариализация отсутствуют.

Установка локальной сборки и запуск выполняются отдельно:

```sh
mkdir -p "$HOME/Applications"
ditto 'build/Touch Bar.app' "$HOME/Applications/Touch Bar.app"
open "$HOME/Applications/Touch Bar.app"
```

Сначала закройте уже установленную версию через её меню. Реальные разрешения и захват клавиатуры проверяет владелец вручную.

## Проверки и упаковка

```sh
./tests/run.sh
./package.sh
```

Упаковка создаёт в `dist/` ZIP и контрольную сумму SHA-256. Скрипт исключает resource forks, расширенные атрибуты и quarantine metadata. Уже опубликованные архивы не заменяются автоматически.

Все тесты безопасно работают без управления настоящей панелью и без блокировки клавиатуры:

- `tests/test-app.m` — команды Touch Bar с fake-клиентом, сохранение выбора при отказе API, отсутствие команд до готовности или без дисплея.
- `tests/test-keyboard.m` — синтетические CGEvent и fake backend: permissions/create/enable, keyboard/media/power, пропуск мыши и scroll, снятие модификаторов, fail-open, sleep/session/terminate и teardown без retain cycle.
- `tests/test-menu.m` — настоящие NSSwitch и AppKit-строки: размер NSMenu и frames одинаковы во всех состояниях и при ошибках; отказ возвращает тумблер в фактическое состояние. Статусы помещаются в выделенную ширину. Создаются `build/tests/menu-light-off.png`, `menu-light-on.png`, `menu-dark-off.png`, `menu-dark-on.png` — offscreen render тех же AppKit views, а не скриншот открытого системного меню.
- Plist, shell-синтаксис и компиляция с предупреждениями как ошибками; скрипт сборки проверяет подпись bundle.

Автоматические тесты не вызывают запрос Универсального доступа, не создают системный event tap и не заменяют ручную приёмку. Новый UI 1.3.1 ещё ожидает проверки владельцем. Владелец подтвердил основную работу версии 1.3.0, но отдельные проверки сна, смены сессии, отказа разрешения, внешней клавиатуры, Secure Input и всех системных сочетаний не зафиксированы.

## Управление Touch Bar

Используется внутренний API Apple `DFRBrightness.framework`; после обновления macOS он может измениться. Проверенный случай гашения остановил белые вспышки на MacBook Pro M1; приложение не ремонтирует панель и не гарантирует одинаковый результат при любой неисправности.

Тумблер показывает выбранный режим, а не измеренное аппаратное состояние. Принятая команда не доказывает физическое снятие питания. macOS может самостоятельно включить панель после системного события. Код повторяет выбранную команду после обычного сна; реальный цикл сна пока отдельно не принят владельцем. При выходе приложение не включает панель принудительно. Работа до входа в учётную запись и на экране блокировки не обещается.

Выбор сохраняется в `NSUserDefaults`, домен `local.touchbaroff.menubar`, ключ `TouchBarEnabled`. Для удаления настройки:

```sh
defaults delete local.touchbaroff.menubar
```

## Блокировка клавиатуры

Контроллер и системный backend находятся в `KeyboardLock.h` / `KeyboardLock.m`. Native AppKit меню в `TouchBarApp.m` использует NSSwitch слева и постоянные подписи справа; вторичные статусы имеют фиксированные frames. On для Touch Bar означает включение панели, on для «Чистка клавиатуры» — активную блокировку. NSMenuItem titles не меняются при переключениях.

Блокировка независима от наличия DFR-клиента. Включение тумблера запрашивает Универсальный доступ и создаёт активный HID `CGEventTap` в начале цепочки. Common run loop modes включают tracking mode меню. Fallback на более поздний session tap отсутствует. После создания проверяется реальная маска через `CGGetEventTapList`: tap с урезанной клавиатурной маской не считается блокировкой. SDK Apple содержит старое ограничение HID tap для root; приложение не запрашивает sudo. Владелец подтвердил основную работу на своём Mac, но это не доказывает доступность такого tap на всех версиях macOS.

Подавляются обычные клавиши, изменения модификаторов и доставленные tap медиасобытия всех клавиатур пользовательской сессии, включая внешние. Выбора устройства нет. Callback не читает символы и не логирует ввод. Touch ID не является обычным клавиатурным CGEvent; известные Power события явно пропускаются. Secure Input, системные сочетания и действия, обработанные macOS раньше tap, могут обходить фильтр. Аппаратное отключение клавиатуры не обещается.

Мышь, трекпад и прокрутка проходят. В pointer/scroll событиях очищаются только флаги Ctrl/Shift/Option/Command/Fn/Caps Lock, чтобы зажатый модификатор не мешал обычному клику разблокировки. Тип, кнопки, координаты, delta и остальные данные сохраняются; жесты не фильтруются.

Lock не сохраняется между запусками. Код снимает блокировку при выходе, сне, потере активной пользовательской сессии и отключении tap системой. Fail-open освобождает tap и обновляет UI, автоматического повторного захвата нет. После пробуждения клавиатура сама не блокируется. Открытие меню перепроверяет активность tap. При принудительном завершении процесса tap исчезает. Статус означает активность фильтра, а не гарантированное подавление всех аппаратных действий.

## Командная строка

```sh
./build.sh
./touchbarctl off     # Погасить
./touchbarctl on      # Включить
./touchbarctl status  # Диагностическое состояние API
```

Числовые значения `state` недокументированы и не доказывают состояние панели. Файлы `Выключить Touch Bar.command` и `Включить Touch Bar.command` запускают только CLI управления панелью; перед использованием соберите `touchbarctl`. Блокировка клавиатуры доступна только в приложении.

## Состав и безопасность

Приложение не устанавливает службы и автозапуск, не выполняет фоновых сетевых запросов, не содержит встроенной аналитики и не показывает иконку в Dock. Ссылка Dzzen.com открывает фиксированный URL с UTM-метками только по нажатию. Перехват клавиатуры не записывает ввод.

Исходники и опубликованные архивы до 1.2.1 прошли отдельную проверку секретов. Этот аудит не распространяется автоматически на 1.3.0/1.3.1. Подробности — в [отчёте проверки](security-check.md).
